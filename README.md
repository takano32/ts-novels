# 少年少女文庫 — ts.novels.jp 復元ミラー

閉鎖された TS（性転換）小説投稿・収蔵サイト **「少年少女文庫」**（`http://ts.novels.jp/`, 2002–2021 頃）を、
複数の Web アーカイブのスナップショットから復元した静的ミラーです。

元サイトは既に消滅しており、本リポジトリは
[Internet Archive Wayback Machine](https://web.archive.org/) を主軸に、
[CommonCrawl](https://commoncrawl.org/)・[archive.today](https://archive.today/)・親サイト `www.novels.jp`・
さらに**各作品の原作者サイト**に残された記録を横断的に収集して再構成したものです。
Wayback に存在しなかったページも、ありとあらゆるアーカイブ・原典から可能な限り回収しています。

## 内容

- **全 4,593 ファイル**（HTML系 3,807 / 画像 781 / その他）
- トップページ `index.html`、目次 `lib*.html` / `lib-index-*.html`、作品本体 `novel/YYYYMM/<投稿ID>/<作品>.html`
- Wayback の ts.novels.jp ミラー（status 200 全 3,828 件）に加え、複数の手段で **計 765 ページを追加回収**:
  - **102 ページ** … CommonCrawl（Wayback 未収録の作品本体）
  - **653 ページ** … 親サイト `www.novels.jp/~ts/`（ts.novels.jp の元となった旧ホーム。作品別の読者**感想掲示板** 304 板、過去ログ掲示板 `2ndbbs`、コラム・日記など、ミラーに無かったコミュニティ層）
  - **10 ページ** … 各作品の**原作者サイト**（下記）

## 復元方法

1. **収集** — Wayback CDX API で `ts.novels.jp` 配下の全 URL を列挙し、ステータス 200 のものを対象に選定。
   各 URL は原則として**最新の 200 スナップショット**を採用（末尾が切り詰められていた 3 件のみ、完全な旧スナップショットを使用）。
2. **取得** — Wayback の `id_`（raw）モードで取得し、ツールバー等の混入のない**原本バイト**を保存。
   さらに **CommonCrawl の全インデックス（2013–2021、83 種）を横断**して `ts.novels.jp/*` のキャプチャを集約し、
   Wayback に無かったページを WARC レンジリクエストで本文取得（**102 ページ**を追加回収）。
   archive.today・国立国会図書館 WARP・ウェブ魚拓（megalodon.jp）も照会したが、いずれも追加分は無し
   （archive.today の 7 件はすべて Wayback と重複）。
   - **親サイト `www.novels.jp`** … ts.novels.jp は `www.novels.jp/~ts/` の別名（vhost）だった。
     旧ホーム `~ts/` 配下に残る読者**感想掲示板**（作品別 304 板）・過去ログ・コラム等 **653 ページ**を Wayback id_ で回収
     （個別投稿 permalink `?res=` は捕捉時点で既に 404 のエラースタブだったため除外）。
   - **原作者サイト** … どのアーカイブにも ts.novels.jp 版が残っていない作品について、
     ミラー内の目次・クレジットから原作者の個人サイトを割り出し、Wayback に残るその個人サイトから同一作品を回収。
     作品名・話数の一致を本文取得で検証して対応付け、**10 ページ**を回収
     （例: ドンノルマの使者 第4〜7話 ← `einhobby.dousetsu.com`、雪月風花〜独奏曲〜 ← `setsugetsuhuuka.com`〔作者サイトでは 1 話＝8 分割のため連結〕、
     みらくる☆ティンクル ← `ts9.jp`、あるけみすと☆さーが ← `geocities.jp/fantasydreamsjp`、絆 ← `yasuragi.or.jp`）。
3. **文字コード変換** — `nkf` による自動判定で UTF-8 へ統一（元は大半が Shift_JIS、一部 ISO-2022-JP、宣言なしのものも含む）。
   `<meta>` の charset 宣言も UTF-8 に書き換え。
4. **リンク書き換え** — サイト内リンク（絶対 `http://ts.novels.jp/...`、ルート絶対 `/...`、`..` を含むものすべて）を
   ブラウザと同じ規則で解決し、各ファイルからの**相対パス**へ変換。
   これにより、ユーザーページ（ルート公開）でもプロジェクトページ（`/<repo>/` のサブパス公開）でも正しく動作します。

## 検証結果

変換後の全 HTML に対するリンク監査:

| 項目 | 件数 |
|---|---|
| 解決する内部リンク | 37,494 |
| 内部絶対リンクの書き換え漏れ | 0 |
| サブパスで壊れるルート絶対リンク | 0 |
| ルート外への `..` リンク | 0 |
| 不正な UTF-8 | 0 |

複数の手段による追加回収（CommonCrawl・`www.novels.jp/~ts`・原作者サイト）で、当初の Wayback ミラー時点から
解決する内部リンクは **33,729 → 37,494 本**（+3,765）に増加しました。
加えて、ローカル HTTP 配信を `/<repo>/` サブパス下で行い、回収ページが 200 応答し内部リンクも解決することを確認済み。

## 既知の欠落

ここまでの横断回収（Wayback Machine／CommonCrawl／`www.novels.jp`／archive.today／NDL WARP／ウェブ魚拓／
各原作者サイト）を尽くしてなお、一部の作品・画像は **どこにも実体が残っておらず**辿れません
（古い平置き構造の作品 `novel/*.html`、各階層の動的インデックス `library.html`、未取得の画像 `.gif`/`.jpg`、
Word 書き出しの補助ファイル `.xml`/`.mso` など）。捕捉されていた数件も捕捉時点で既に 404 でした。
具体例として、シリーズ目次が参照する `sebaschan.htm` と `ama.htm` の 2 話は、
共同企画「二代目は……」の参加作で、原作者サイト（`minafumi.aki.gs`）には企画ルールページのみが残り
作品本体は収録されていなかったため、回収できませんでした（同シリーズの他 9 話は復元済み）。

また、`cgi-bin/` 配下の掲示板・新着リスト・カウンタ等の動的ページは、当時生成された HTML スナップショットとして保存していますが、
CGI としては動作しません（静的な記録のみ）。

## 公開（GitHub Pages）

`master` ブランチへの push で `.github/workflows/deploy-pages.yml` が動作し、GitHub Pages へ自動デプロイされます。
初回のみ **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** に設定してください。

## リポジトリ構成・履歴

- タグ **`raw-original`** … Wayback 由来分について、UTF-8 変換・リンク書き換えを行う**前**の原本バイト（Shift_JIS 等のまま）。
  変換結果と原本を比較したい場合や、再変換のやり直しに使えます。
  追加回収分（CommonCrawl 102・`www.novels.jp/~ts` 653・原作者サイト 10）も、いずれも
  変換前の生バイト（Shift_JIS / CP932 / EUC-JP）をいったんコミットしてから UTF-8 化しており、
  各 raw コミットが履歴に残っています。
- `.nojekyll` … GitHub Pages の Jekyll 処理を無効化（特殊なファイル名の取りこぼし防止）。
