# 用語集

本プロジェクト固有の語を定義します。文書間で語の意味が揺れたら、ここが正典です。
(収蔵物の実体と件数は [data-inventory.md](data-inventory.md)、環境は [environment.md](environment.md))

## サイトと世代

**少年少女文庫** — 本プロジェクトが復元している TS(性転換)小説の投稿・収蔵サイト。
1997 年に八重洲メディアリサーチが設立、`www14.big.or.jp/~yays` で運営 → 後に別の管理者へ移管され
`ts.novels.jp` へ → 移管先の管理者が保守を止め 2021 年頃に消滅。現在は設立者の依頼でリブート中。

**世代** — 文庫がホストを移すたびに変わったサイトの姿。古い順に
① 前史(`www2.tomato.ne.jp/~ezpe`、1999 頃)
② 八重洲期(`www14.big.or.jp/~yays`、〜2003 頃)
③ 本体期(`ts.novels.jp` / `www.novels.jp`、2002–2021)
④ 閉鎖後の姉妹ドメイン(`ts.novels.name`・`kirika.novels.name`・`ts.raa0121.info`)
⑤ 2018 年の再建版(`ts-novels.jp`)。
ミラーではホスト名のディレクトリで世代を分けて収蔵している。

### 三館の呼び分け(**内部用語。利用者に見せる文面では使わない**)

プロジェクト内の文書・コミットメッセージ・コード中では次の 3 語で呼び分ける。
**サイト上の表示文言・about ページ・バナーなど、読者の目に触れる場所では使わない**こと
(読者には「原本を見る」「当時のページ」のように、具体的に何であるかを書く)。

| 語 | 指すもの | 実体 |
|---|---|---|
| **本館** | 移築先の WordPress ライブラリ | `novels.xwp.jp`。目録データで体系化した読書・発見の層 |
| **別館** | 原本をそのまま保つミラー | 現行の GitHub Pages(全 17,000 ファイル超)。当時の URL 空間を改変せず保持する。本館に載せられないもの(`.cgi` を含む URL は移築先が 403 にする)もここで生きる |
| **旧館** | サルベージ元 = 消滅した原サイト | `ts.novels.jp` とその全世代(前史 `~ezpe`・八重洲期 `~yays`・閉鎖後の姉妹ドメイン)。**もう存在しない**。「旧館にはあったが回収できていない」のように使う |

本館の各話から「原本を見る」で別館へ、別館からはバナーで本館へ、相互に往還する。
(2026-08-30 に旧称カタカナ語・「整理版」から本語彙へ置き換えた)

## 目録とデータ

**目録(カタログ)** — 文庫が管理 CGI(`manage2.cgi`)で生成していた作品一覧ページ群
(`lib1.html`〜`lib73.html`)。1 作品 1 テーブルで、題名・作者・画師・掲載日・サイズ・感想板リンク・
あらすじ・コメント・オススメ作品・推薦文・ジャンル・種別・キーワードを持つ。**移築のメタデータの
一次資料**。ゼロ埋めの `lib01.html`〜`lib09.html` は**別物の旧目録**(1997–98、非テーブル形式)。

**エントリ** — 目録の 1 テーブル = 1 話の掲載記録。**話を一意に定める自然な単位**
(ファイルでもディレクトリでもない — 1 ファイルに複数話が同居する例、同じ話が複数ディレクトリに
重複する例があるため)。

**話(Episode)** — 読者が 1 回で読む単位。目録エントリに対応する。WordPress では
`ts_work` の子投稿。

**作品(Work)** — 連載・シリーズをまとめた単位。目録には存在せず、`series.html`・
共有世界一覧・シリーズタイトルページ・推薦文内のナビリンクから**合成する**。
WordPress では `ts_work` の親投稿。単発作品は Work = Episode の 1 対 1。

**episode_id** — 全フェーズを貫く結合キー。`source_path` の `/` を `__` に置換し、
アンカーがあれば `@<anchor>`、同一ファイルを指すエントリが複数ある衝突グループのみ
さらに `+<掲載日YYYYMMDD>` を付けたもの。例 `novel__200209__19204751__d_upboy06.htm`。
**正典は `catalog/episodes.jsonl` の `episode_id` 欄**で、再導出しない。
`catalog/episodes.jsonl` ↔ `bodies/` ↔ `convert_report` ↔ WordPress の import は
すべてこの id で結合する。

**corpus 区分** — 話の出自の分類。
`honkan`(正規目録 lib1–73 由来)/ `legacy`(旧目録 lib01–09 由来)/
`uncatalogued`(ファイルは実在するがどの目録にも載っていないもの)/
`extern-repost`(文庫には未掲載で、作者の再掲載など外部由来のもの)/ `dojo`(ストーリー道場の作品)。

**provenance** — 各話の**回収経路**。Wayback / CommonCrawl / ウェブ魚拓 / 作者サイト /
pixiv 等のどこから、いつ取得したか。出所の明示は権利上の配慮の中核であり、
書誌カードに表示する。出所は git の回収コミット履歴から算出する。

## 復元・回収の技法

**CDX** — Wayback Machine のインデックス API。URL・タイムスタンプ・ステータス・記録長を
一覧できる。**記録長(length)の分布**でエラーページと実体を機械判別するのが本プロジェクトの定石
(エラースタブ ≈ 400B、実体 = 数 KB 以上)。

**zipnum** — CommonCrawl のインデックス形式。`cluster.idx` を HTTP レンジで二分探索し、
該当する `cdx-*.gz` ブロックだけを取得すれば、API を介さず全コレクションを照会できる。

**ウェブ魚拓**(megalodon.jp) — 日本の Web 保存サービス。`/?url=<URL>` で捕獲一覧、
`/ref/<日時>/<host/path>` で原本バイトが取れる。「真に喪失」としていた作品を発見した実績がある。

**soft-404** — 消えたファイルに対してサーバが 200 を返し、広告やエラー案内を表示する状態。
本プロジェクトでは `www14.big.or.jp` が該当し、応答サイズと本文マーカーで機械判定している。

**ギャップフィル** — 世代間で同じファイル名を照合し、本体ツリーの欠落を旧世代ツリー
(`~yays/library` など)の同名ファイルで埋める手法。**一意に一致する場合のみ**行う。

## 移築の方針

**最大掲載原則**(設計 v1.4) — サルベージしたもの・できるものはすべて掲載する。
掲載しない例外は **denylist / スパム / メールアドレス** の 3 つだけ。

**無損失証明** — 本文 HTML を Markdown へ変換するときに、「タグ・空白・山括弧を除いて
NFC 正規化した文字列が原本と完全一致すること」を機械検証する仕組み。
**証明に通った話だけ** Markdown を正準とし、通らない話は原本 HTML のまま載せる
(raw フォールバック)。「気づかれない本文改変」を構造的に防ぐための装置。

**書誌カード** — 各話の末尾に置く出自の表示。初出日・当時の URL・回収経路・
「原本を見る(別館)」・「初出時の姿(~yays 版)」・「当時の感想を読む」を並べる。

**感想板** — 作品ごと(正確には**作者ごと**)に立てられていた読者感想の掲示板
(`~ts/kansou/bbs@log_<作者slug>.cgi`)。約 3,978 投稿を復元済み。WordPress では
`/boards/<作者slug>/` に**読み取り専用の近代ビュー**として再現する(投稿フォームは置かない)。
板は作者単位なので、個々の作品のコメント欄に流用すると史料の改竄になる — しない。

**道場** — 第二掲示板「ストーリー道場」(`~ts/bbs/2ndbbs/`)。作品そのものが掲示板に投稿され、
同じページに読者の感想が埋め込まれている層。感想と作品の紐付けが自明な唯一の層。

**noteky** — 前史・八重洲期に使われていた推薦ノート CGI。`~ezpe/cgi-bin/noteky`(「私のオススメ」、
市販作品も含む推薦)と `~yays/cgi-bin/noteky`(文庫作品の感想ボード)の 2 系統があり、中身は別物。

**denylist 四層** — 削除依頼への対応。`takedown/denylist.yml` 1 ファイルを唯一の情報源として、
① WordPress で draft 化 ② `.htaccess` で 410 Gone ③ 別館(Pages)のビルドから除外
④ git 履歴からの除去、の四層を同期させ、加えて `/removed/` に掲載記録を残す(**四層+掲示**)。
受領から **72 時間以内**の非公開化を宣言している。

## 移築先の環境

**xwp** — Xserver for WordPress(`novels.xwp.jp`、`ssh novels`)。nginx キャッシュ → Apache →
PHP 8.0 の構成。**ファイル名に `.cgi` を含む URL を前段の nginx が一律 403 にする**制約があり、
これが別館を GitHub Pages に残す直接の理由。詳細は [environment.md](environment.md)。

**mu-plugin** — `wp-content/mu-plugins/ts-library/`。投稿タイプ・タクソノミー・メタ・
WP-CLI コマンドを定義する自作プラグイン。管理画面から無効化できない場所に置くことで、
事故でコンテンツモデルが消えるのを防ぐ。

**`wp ts` コマンド** — mu-plugin が提供する WP-CLI サブコマンド群
(`sync-terms` / `import` / `apply-takedown` / `verify` / `export-pathmap`)。
インポートは冪等で、**2 回連続実行したときの 2 回目が created=0 / updated=0** になることが
受け入れ条件。
