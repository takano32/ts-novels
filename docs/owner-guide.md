# 八重洲さんと運営委員の方へ

サイト所有者の八重洲さんと、これから運営委員になる方に向けて、WP サイトでいま何ができるか、
取り下げや版違いがどう扱われるか、判断をお願いしたいことをまとめます。
**「いま」と「予定」を分けて**書いています。括弧内の番号 (S.n・T.n) は、詳しいことが書いてある文書の番号です。

このページでは、移築先の WordPress を「WP サイト」、GitHub Pages で原本をそのまま保っているミラーを「原本アーカイブ」と呼びます。
読者に見せる画面ではこの呼び方は使っていません (S.15)。

## サイトでいま見られるもの

`https://novels.xwp.jp` は公開状態で、検索エンジンにも載る設定です (S.42、S.203)。

- **トップ** — 毎時替わる「いまの一作」と、開くたびに入れ替わる作品の並び (S.195)
- **作品と話** — 連載は作品ページに目次が並び、各話の末尾に初出・回収経路・「原本を見る」を並べた書誌カードがあります (S.18、S.192)
- **作者ページ・索引・年別一覧・検索** — 作者さくいん・年表・分類さくいん・キーワードさくいんなどと、分類で絞り込める検索 (S.92、S.194、S.196)
- **運営文書とギャラリー** — 編集"好"記・巻頭言などと、`~yays` 時代のギャラリーの CG 145 点 (S.197、S.200)
- **固定ページ 4 枚** — このサイトについて (`/about/`)・原本アーカイブ (`/archive/`)・掲載の取り下げについて (`/takedown/`)・取り下げ済みの一覧 (`/removed/`) (S.200)

レビュー用の URL の一覧は S.92 にあります。話ページの操作列 (文字サイズ・行間・ダークモード・しおり・矢印キーでの話送り) と
スマートフォンでの見え方は、ブラウザでないと確かめられないので、触っていただけると助かります (S.93)。

古い表示が出たときは配信のキャッシュです。URL の末尾に `?x=1` のような適当な文字を足すと最新が見えます (S.92)。

## 直してほしいところの伝え方

「どの URL (または話) の、何が、どうあってほしいか」を 1 件ずつ書いていただければ十分です (S.95)。
作業側はそれを、slug・作品のまとめ方・作者・取り下げなどの直す場所に振り分けてやり直します (S.72、S.74)。
WP サイトはいつでも目録データから作り直せる作りなので、やり直しは何度でも安全にできます (S.72)。

## 取り下げの扱い

### いま

- 作者の申し出で公開停止になっていた 9 作品と、オフ会レポート 2 件 (写真を含む) を取り下げています (S.97)。
  取り下げた作品の URL は 410 (もう無い) を返します (S.97)。
- Marie 氏の作品 (7 作品・28 話) は 2026-10-27 に取り下げました。WP サイトの 33 投稿を非公開にして URL は 410、原本アーカイブからもご本人のファイル 28 本を外しています (S.235、T.18)。
  申し出の時期、`/removed/` に名前を出すか、他の作者と同居するファイル 2 本と感想板の扱いは確認をお願いしています (S.103、S.114)。
- **窓口が機能していません。** `/takedown/` は GitHub の Issue を案内していますが、Issue は無効になっています (S.112)。
  まずメールの窓口に直します。公開してよいアドレスと暫定の文面の承認をお願いします (T.17.1、S.134)。
- 「72 時間以内に対応」という約束はやめることにしました (S.43)。

### 予定

- 取り下げた作品は消さずに非公開にし、**運営委員としてログインすれば読める**ようにします。
  読者には「作者の申し出により掲載していません」と案内し、取り下げ済みの一覧へ誘導します (S.43、S.118)。
- 申し出は `/takedown/` のフォームで受け付けます。依頼者が確認メールのリンクを開いた時点で受け付けとなり、**その 10 日後に自動で非公開**になります (S.126)。
- 運営委員は、申請ごとに **承認して即時に非公開 / 却下 (自動の非公開を止める) / 復帰 / 期限の変更** ができます (S.128)。
  確認が済んだとき、自動で非公開になる 3 日前、適用したときに、運営委員にメールが届きます (S.129)。
- `/removed/` には作品名と時期だけを載せ、理由は載せません。名前を出すかは依頼者が選べます (S.131、S.124)。
- 原本アーカイブにはログインの仕組みが無いので、取り下げた作品はそこからも外します (読者には 404)。
  旧い内容を見たいときは、公開している git リポジトリで読めます (S.102)。
- git の履歴からまで消すのは、依頼者が配布そのものを止めてほしいと明示したときだけです (S.79)。

## 版違いと作品のまとめ方 (予定)

- **版違い** — 同じ作者の同じ作品が、掲載し直しなどで別のファイルとして複数ある組が 303 組あります (S.144)。
  掲載日の新しい版を残し、古い版は運営委員だけが読めるようにします。読者が古い版の URL を開くと「見つかりません」(404) になり、新しい版へは転送しません。「旧版あり」の案内は運営委員としてログインしているときだけ出ます。
  原本アーカイブには全部の版をそのまま置きます (S.43、S.142)。
  本文が一致するか、ほぼ同じ (類似度 0.95 以上) 組は自動で、それ以外の 89 組は人の確認が要ります (S.144)。
  これは「載せない」のではなく版の整理という扱いです (S.43)。
- **作品のまとめ方** — 自動で束ねた連載に、別の作品が混ざっている疑いのあるものが 71 作品あります (S.107)。
  作業側が振り分けの案を書いた資料を作りますので、承認か修正だけをお願いする形を考えています (S.149)。
  束ね直して URL が変わった作品も、古い URL からの転送はしません (まだ誰もユーザがいないため。S.221)。

## CGI の件について

「CGI のスクリプトがそのまま落ちてくる」とご指摘いただいた件は、配信中の全ファイルを調べ、
スクリプトのソースもパスワードも含まれていないことを確かめました。
ダウンロードになるのは、GitHub Pages が `.cgi` の名前のファイル (中身は当時の画面の保存) をそのような形式で返すためです (S.110)。
サーバのパスが見えるエラー出力 2 本を削除し (T.16.2)、今後は収蔵のたびに機械で検査する予定です (S.110、S.111、T.16.3)。
ダウンロードにならない配信の形は、原本アーカイブの配信を作り直すときに入れます (T.16.5)。
