# S242 PHP (mu-plugin ts-library・テーマ ts-bunko) のファイル構成と試験 (T45.1 の記録)

- 種類: 記録
- 状態: 有効
- 出典: 2026-11-05 の作業 (T45.1)
- 関連: T45.1, T45, S181, S19

mu-plugin `mu-plugins/ts-library/` を、WordPress を使わない部分 (判断・計算・文面) と WordPress に触る部分 (フック・DB・出力) と WP-CLI のコマンドに分け、小さなファイルに割った記録。外から見える振る舞い (`wp ts` の名前・引数・出力、フック、ショートコード、option・meta、URL と応答、HTML) は分割前 (`d586f0eb`) と同じにした。分割の後に純粋な関数へ出したもの・試験を足したもの・型の寛容さを旧に揃えたものも、行ごとに T45.1 の小タスクにある。

## ファイルの構成

`ts-library.php` は `includes/files.php` の `TS_Library_Files` の 3 つの表に書いたファイルだけを、表の順に require する。glob は使わない。配備 (`scripts/wp/deploy.sh`) は rsync に `--delete` を付けないので、消したり名前を変えたファイルが本番に残る。glob で読むと残った古いファイルまで読まれ、関数の二重定義で落ちる。

| 表 | いつ読むか | 中身 |
|---|---|---|
| `PURE` | いつも (最初) | WordPress を使わない部分。単体の試験はこの表だけを WordPress なしで読む |
| `WP` | いつも (`PURE` の後) | WordPress に触る部分。先頭は `site-hooks.php` (`TS_Library::boot` の `pre_get_posts` を、索引と年別の一覧の `pre_get_posts` より先に登録するため。後から登録した側が `posts_per_page` と `orderby` を上書きする) |
| `CLI` | `WP_CLI` のときだけ (最後) | `wp ts` のサブコマンド。`TS_Command_Base` を継ぐサブコマンドごとのクラスで、最後の `commands/register.php` が `WP_CLI::add_command` で登録する |

`PURE` の中の順は、読み込み時に別のクラスを要らないので意味は無い (クラス定数と静的メソッドは呼ぶときに引く)。`WP` と `CLI` の中は、フックの登録の順と、継承 (`TS_Command_Base` が先) の順。

## WordPress を使わない部分と使う部分の境目

`PURE` の表のファイルは、PHP の組み込み関数と `PURE` の中で定義した関数とクラスしか呼ばない。WordPress の関数・グローバル変数 `$wpdb` に触るもの (DB・フック・出力・エスケープ・日時の表示 `wp_date`・`sanitize_title`・`wp_json_encode`) は `WP` と `CLI` の側に置き、純粋な側には値か callable で渡す (例: `TS_Work_Index::child_slugs` の `$sanitize`、`TS_Takedown_Input::validate` の `$resolve` と `$is_email`、`TS_Takedown_Rules::params` の `$defined`)。エスケープは呼び出し側で行い、純粋な側はエスケープ済みの文字列を受ける (例: `TS_Takedown_Text::respond('invalid', …)` の `items`)。

境目は `scripts/wp/tests/files.php` が機械的に見る: `PURE` の各ファイルを `token_get_all` で読み、関数呼び出し (直前が `->`・`?->`・`::`・`function`・`new` でない名前の直後に `(`) のうち、組み込み関数でも `PURE` の外側で定義した関数・クラスでもないものが 0 件で、`$wpdb` も 0 件。理由つきの許可リストはいまは空 (`is_email` は T45.1.20 で注入に替えて外した)。さらに、どのファイルも `$GLOBALS` を使わない (要求の中の状態はクラスの static プロパティに置く。T45.1.19.4)。

純粋な側へ出さなかったもの:

- import の hash (`md5(HASH_VER . wp_json_encode(…))`) は WordPress 側に残す。`wp_json_encode` は不正な UTF-8 を直してから符号化するので、純粋な側で `json_encode` に替えると hash が変わり得る。hash が変わると本番の全投稿が updated になり、手動編集の保護の判定も動く。
- upsert の分岐 (T45.1.16.1)・申請の適用と復帰の判断 (T45.1.17.3)・子孫の集め方 (T45.1.19.3) は、旧と同じ順序を WordPress の代わり (T45.1.14) で確かめてから出すので、まだ WordPress 側にある。

## 試験

`make test-php` (`scripts/wp/php_test.sh`) で流す。手元に PHP が無く、docker も立てない決まりなので、`scripts/wp/deploy.sh` の構文検査と同じ形で、対象を tar でサーバに送り、一時ディレクトリに展開して `php -l` (本番の PHP 8.0.30) と `scripts/wp/ts_library_test.php` を流して消す。公開ルートと DB には触れない。

`scripts/wp/ts_library_test.php` は `PURE` を WordPress なしで読み (読めること自体が境目の検査)、`CLI` も登録を受けるだけの `WP_CLI` の代わりを置いて読む。試験の本体は `scripts/wp/tests/*.php` に領域ごとに置き、`ts_library_test.php` に書いた順に読む (`files`・`content-model`・`site`・`roles`・`visibility`・`takedown`・`denylist`・`catalog`・`eyecatch`・`render`・`indexes`)。

件数: 分割前 pass=120、分割の直後 pass=320、T45.1.12〜T45.1.20 の後 pass=414 (2026-11-05、fail=0)。WordPress に触る側 (`WP` の表) の HTML の試験は、WordPress の代わりを置く土台 (T45.1.14) の後 (T45.1.15)。

## 純粋な関数に出したときの判断 (T45.1.16 以降)

- `TS_Episode_Fields::body` (T45.1.16.2) は `--bodies` の有無を 3 つ目の引数 `$bodies` で受ける。状態とペイロードの 2 つだけでは「メタのみ投入 (null)」と「ペイロードが無い (案内文)」を分けられないため。ペイロードのファイルを読むのは `includes/commands/import.php` に残し、取り下げ対象なら読まないのも分割前と同じ。
- `TS_Work_Index::parent_term_values` (T45.1.16.3) は、連載の親 work に合併する値を work ごとに束ねずに、話ごと (episodes の添字 => work と taxonomy ごとの値) に返す。import は分割前と同じく話ごとに `TS_Term_Resolver::term_ids` を呼び、term ID で束ねる。束ねてから 1 度に呼ぶと、解決できなかった値を数える順 (`ts_term_warnings` と警告の「上位」の並び。`arsort` は同点なら入れた順) が変わるため。
- `wp ts verify` の親 work の期待値 (`TS_Verify_Expect::assignment_counts` の `parent_expect`) は `parent_term_values` を使わず、別の実装のまま残す。verify の役目は importer と独立に数え直して取り違えを見つけることで、同じ関数を使うと importer の誤りを期待値も写してしまう。
