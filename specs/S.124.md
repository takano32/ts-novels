## 取り下げフォームと 10 日後の自動適用の仕様 (2026-10-26)

**位置づけ**: 72 時間の約束を撤回して取り下げフォームにする決定 (S.43。72 時間 SLA を撤回し、フォーム → 確認メール → 10 日後に自動で非公開 → 運営委員が上書き) の実装仕様。
根拠と現状は S.112、実装タスクは `TASKS.md` の T.26。
非公開化の振る舞い (private・410・帯) は S.116〜S.123 を優先する。
所有者の裁定待ちのパラメータは S.135 の表にまとめ、**既定値で実装して裁定後に定数を変える**。

### 窓口

- `/takedown/` 固定ページにショートコード `[ts_takedown_form]` (mu-plugin)。送信先は `admin-post.php?action=ts_takedown` (`admin_post_nopriv_ts_takedown`)。外部のフォームプラグインは入れない (S.31 プラグイン最小構成)。
- GitHub Issue の案内は**載せない** (S.28 で不採用。現在のページの記載は誤り)。メール窓口 (八重洲さん・高野さんが決めるアドレス) を併記し、メール経由の申し出は運営委員が手で申請を起票して同じ状態機械に乗せる。

| 項目 (name) | 必須 | 形 | 検証 |
|---|---|---|---|
| `pen_name` 当時のペンネーム | 必須 | 1〜100 字 | — |
| `targets` 対象作品の URL | 必須 | 1〜20 行 | 本サイトの `/novel/…` で `ts_work` に解決できること。解決できない行は保存して警告フラグ |
| `contact` 連絡先メール | 必須 | email | `is_email()` |
| `relation` 立場 | 必須 | `author` 作者本人 / `heir` 権利継承者 / `other` | enum |
| `evidence` 本人確認の手がかり | 任意 | 1,000 字 | — |
| `message` 自由記述 | 任意 | 2,000 字 | — |
| `allow_name` 名前の掲示 | 任意 | checkbox | `/removed/` にペンネームを出してよいか (既定: 出さない) |
| `hp` | — | honeypot (CSS で隠す) | 非空なら 400 |
| `t` | — | フォーム表示時刻 | 送信まで 3 秒未満なら 400 |
| `_wpnonce` | — | nonce | 不一致は 403 |

- レート制限: 送信元 IP の SHA-256 (salt = `AUTH_SALT`) をキーに transient で **1 時間 3 件**。超過は 429。IP そのものは保存しない。
- 成功時: `unconfirmed` の申請を作り、受付の確認メール (S.129 の受付のメール) を送って「確認メールを送りました」ページ (200) を返す。

## 実装の記録 (2026-10-30、T.26.3。未配備)

`mu-plugins/ts-library/includes/takedown-request.php` (フォーム・確認リンク・cron・一覧) と `includes/takedown-admin.php` (管理画面)。判定と文面は WordPress を使わない関数にして `scripts/wp/ts_library_test.php` で試す。表に無いので決めて作った所:

- 裁定待ちのパラメータ (S.135) と S.126 の定数は既定値で動き、`wp-config.php` で `TS_TAKEDOWN_AUTO_APPLY_DAYS` のように `TS_TAKEDOWN_` を付けた同名の定数を先に define すれば変えられる (確認メールの要否は `TS_TAKEDOWN_REQUIRE_CONFIRM`、通知先は `TS_TAKEDOWN_NOTIFY_TO` (カンマ区切り。空なら admin_email + 運営委員全員)、却下のメールは `TS_TAKEDOWN_SEND_REJECT_MAIL`)。窓口メールアドレスは固定ページの文面に書くので定数にしていない (T.26.5)。
- フォームの項目の見出しは表の項目名どおり。フォームの前後の説明文は固定ページ (T.26.5) に書く。
- `t` (フォーム表示時刻) は `AUTH_SALT` 系の鍵で署名した値にし、署名が合わなければ 400 (送信者が書き換えて 3 秒の検査を逃れないように)。
- 検査の順は nonce 403 → honeypot 400 → 3 秒未満 400 → レート制限 429 → 入力の検証 400。入力の不備は 400 で何が足りないかを並べる。レート制限は受け付けた件数で数える (不備で止めた送信は数えない。申請もメールも作らないため)。
- 送信元は `REMOTE_ADDR` だけを使う (`X-Forwarded-For` は書き換えられるので信じない)。前段の nginx を通った要求の `REMOTE_ADDR` が利用者の IP か、配備後に確かめる (全員が同じ値なら全員で 1 時間 3 件になる)。
- 対象作品の URL: 1 行 500 字まで。同じ行の重複は 1 つに。ホストを省いた `/novel/…` と、スキームを省いた `novels.xwp.jp/novel/…` も本サイトとみなす。話の URL は話の投稿に結びつく (作品全体には広げない)。
- 応答のページ (受付・確認・各エラー) は WordPress の簡素な画面 (`wp_die`) で、状態コードを付けて返す。固定ページにショートコードを置く前でも同じに見える。
- 依頼者宛のメール (受付・適用・却下) には依頼者の入力した文字列を入れない。他人のアドレスを書いてこのサイトから任意の文面を送らせる中継に使わせないため。運営委員宛の要約は書式なしのテキストで、件名には入力を入れない。
- フォームか一覧のショートコードを置いたページには `nocache_headers()` を付ける (nonce と表示時刻が前段のキャッシュで古くならないように)。nginx がこれを守るかは配備後に確かめる (古いページが 24 時間を超えて返ると nonce が切れて 403 になる)。
- 送信先の `admin-post.php` は `/wp-admin/` の下にあるので、サーバの管理画面向けの接続制限 (国外からの接続の制限など) に当たらないかを配備後に確かめる。
- メールで届いた申し出は、管理画面の「申請を起票」で同じ項目を入れて保存すると、確認済み (`received`) として自動適用の待機に入る (経路はメタ `_tr_via=email`)。
