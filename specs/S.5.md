## 作業のしかた(全セッション共通)

1. 担当タスクを TASKS.md と関連する S で確認し、**受け入れ条件を満たすまで**やる。満たせないときは正直に報告する
   (数値をごまかさない)
2. **単一真実源は `catalog/`**。WordPress の DB は使い捨ての派生ビューで、`wp ts import` で
   いつでも再構築できる。WP 管理画面での手動編集は禁止、修正は catalog 側の overrides で。
   例外は所有者による固定ページ 4 枚 (`content/pages/*.html`) と解題 (`content/docs/*.html`) の編集 (S.100)。
   ここも git のファイルが正のままで、所有者の原稿を作業側がファイルに入れても、所有者が管理画面で直したものを
   作業側が git に書き戻しても (固定ページは `wp ts export-pages`、S.109)、git に入ってから投入する。
   どちらの経路にするかは八重洲さんの判断 (T.27.1)。所有者文責の注記 `owner-authored` のあるページは
   所有者文責の部分を書き換えない (S.109)
3. 新しいスクリプトは `scripts/`(移築用は `scripts/wp/`)に置き、ツールの一覧 S.209 / S.210 (元の `scripts/README.md`) に 1 行足す
4. コミットは日本語。タスクを終えたら TASKS.md の `[ ]` を `[x]` にして一緒にコミットする
5. **作者・関係者への連絡は人間が行う**。セッションからは一切しない
6. 本番サーバの危険操作の前に復旧点を作る(S.59〜S.68 のチェックリスト)
