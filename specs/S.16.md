## 目録とデータ

**目録(カタログ)** — 文庫が管理 CGI(`manage2.cgi`)で生成していた作品一覧ページ群
(`lib1.html`〜`lib73.html`)。1 作品 1 テーブルで、題名・作者・画師・掲載日・サイズ・感想板リンク・
あらすじ・コメント・オススメ作品・推薦文・ジャンル・種別・キーワードを持つ。**移築のメタデータの
一次資料**。ゼロ埋めの `lib01.html`〜`lib09.html` は**別物の旧目録**(1997–98、非テーブル形式)。

**エントリ** — 目録の 1 テーブル = 1 話の掲載記録。**話を一意に定める自然な単位**
(ファイルでもディレクトリでもない — 1 ファイルに複数話が同居する例、同じ話が複数ディレクトリに
重複する例があるため)。

**話(Episode)** — 読者が 1 回で読む単位。目録エントリに対応する。WordPress では
`ts_work` の子投稿。

**作品(Work)** — 連載・シリーズをまとめた単位。目録には存在せず、`series.html`・
共有世界一覧・シリーズタイトルページ・推薦文内のナビリンクから**合成する**。
WordPress では `ts_work` の親投稿。単発作品は Work = Episode の 1 対 1。

**episode_id** — 全フェーズを貫く結合キー。`source_path` の `/` を `__` に置換し、
アンカーがあれば `@<anchor>`、同一ファイルを指すエントリが複数ある衝突グループのみ
さらに `+<掲載日YYYYMMDD>` を付けたもの。例 `novel__200209__19204751__d_upboy06.htm`。
**優先するのは `catalog/episodes.jsonl` の `episode_id` 欄**で、再導出しない。
`catalog/episodes.jsonl` ↔ `bodies/` ↔ `convert_report` ↔ WordPress の import は
すべてこの id で結合する。

**corpus 区分** — 話の出自の分類。実データ(`catalog/episodes.jsonl`)で使われている値と、
表示に使う日本語は次のとおり。

| 値 | 表示名 | 意味 | 件数(2026-08-30) |
|---|---|---|---:|
| `honkan` | 正規目録 (lib1–73) | 正規目録由来 | 2,887 |
| `legacy` | 旧目録 (lib01–09) | 旧目録の差分 | 97 |
| `uncatalogued` | 目録外収蔵 | ファイルは実在するがどの目録にも載っていない | 859 |
| `extern-repost` | 文庫未掲載 | 作者の再掲載など外部由来。文庫に載ったことがない | 1+ |
| `dojo` | ストーリー道場 | 第二掲示板に投稿された作品(T.36 で追加) | 未投入 |

**注意**: 値 `honkan` は「正規目録由来」の意味であり、**WP サイト (移築先 WordPress。S.15。以前は「本館」と呼んでいた)とは
別の概念**。日本語で書くときは必ず「正規目録 (lib1–73)」と表記し、「本館」とは書かないこと
(値名 `honkan` 自体は互換のため変えない)。

**provenance** — 各話の**回収経路**。Wayback / CommonCrawl / ウェブ魚拓 / 作者サイト /
pixiv 等のどこから、いつ取得したか。出所の明示は権利上の配慮の中核であり、
書誌カードに表示する。出所は git の回収コミット履歴から算出する。
