# S.219 文書の検査 scripts/doc_check.py の仕様

- 種類: 仕様
- 状態: 有効
- 出典: 2026-10-26 に文書を docs / specs / tasks の 3 分類に揃えたときに作った (S.220)
- 関連: T.22.5, T.22.6, S.2, S.4, S.220, S.221

## 何を調べるか

`scripts/doc_check.py` は、文書の番号・リンク・決まりが守られているかを機械で確かめる。`make check` の最後に走る。
対象はルートの `README.md`・`DOCS.md`・`SPECS.md`・`TASKS.md`、`docs/`・`specs/`・`tasks/` の全ファイル、
ディレクトリに残した案内 (`scripts/README.md`・`catalog/README.md`・`catalog/review/README.md`・`takedown/README.md`)。

| 種類 | 調べること |
|---|---|
| S | 本文の `S.n` と `S.n〜S.m` の両端が `specs/S.n.md` として実在する (「次は S.n」はまだ無い番号の予告なので見ない。正しさは list で見る) |
| T | 本文の `T.n`・`T.n.m`… が、`tasks/T.n.md` の見出しか、小・孫タスクの行 (`- [ ] T.n.m …`) として実在する (「次は T.n」は S と同じく見ない) |
| deny | `takedown/denylist.yml` の各 `id` が S 番号で、`specs/S.n.md` として実在する (取り下げ 1 件ごとの記録の S。2026-10-27 から。S.221) |
| link | Markdown の相対リンク `[..](path)` の行き先が実在する (`http:`・`https:`・`mailto:`・`#` で始まるもの、コード片 (バッククォートの中) は見ない) |
| list | `SPECS.md` の一覧と `specs/` の一致 (欠け・重複・番号の飛び、各 S の 1 行目の題名・種類・状態が一覧と同じ)、`TASKS.md` の一覧と `tasks/` の一致 (欠け・重複、題名・状態)、「いまの最後は … 次は …」が実際の最後の番号と合う |
| format | `tasks/T.n.md` の書式 — 1 行目 `# T.n 題名`、3 行目 `- 状態: 完了 / 未了 / 一部完了`、4 行目 `- 関連: …`、小・孫タスクの番号が `T.n.` で始まる、状態がチェックボックスと合う (すべて [x] なら完了、すべて [ ] なら未了、混在なら一部完了) |
| word | 使わない語 — 廃止した取り下げ番号 (年と 4 桁の連番の形、TD と数字の形) と廃止した TODO.md、`§`、`台帳`、`Phase` + 数字、`CP-4`、`👤`、`本館`・`別館`・`旧館`、`正典`、`Tier A/B/C`、単独の `OF`・`VR`・`TF`・`VS`・`CO` (SPECS.md の決まり 4 の「独自の略記・記号・概念は使わない」を機械で見る分)。2026-10-26 から、エージェントが作った識別子も見る — 要決定事項の番号 (`Q` + 数字)、記号 `(A)`〜`(H)`、丸数字、設計の版 (`v1.` + 数字)、ランブック・仕様の版 (`v0`・`v1`)、計画の「第 n 段」、S の中の項目を記号や番号で指す「S.n の 英字」「S.n の 番号」(「S.114 の 11 項目」のような数は除く)、「決定」+ 数字、取り下げ番号の旧略記 (`TD-0`)、`cat` + 数字、`T0`・`T+n`、「審査員」+ 番号、旧タスクリストの番号 (「元の n.n」、`- [x] n.n` の行)、「n 節」「節 n」、「A 案」、「補足・原則・ルール」+ 数字。T 番号・S 番号・TD 番号か、見出しや中身の言葉に置き換える |

問題が 1 件でもあれば `[NG ]` の行を出して終了コード 1。問題が無ければ `[OK ] 文書の検査: 問題 0 件` の 1 行。

## 許可リスト

正当な残り (使わない語を禁じる規則そのものの引用、元の文書の節名を写した「出典」、コード片、旧番号の対応表、まだ無い番号の予告など) は
`scripts/doc_check_allow.tsv` に 1 行ずつ書く。列はタブ区切りで「パス (glob 可) / 種類 (上の表の S・T・link・list・format・word) / 行に含まれる文字列 / 理由」。
理由の無い行は受け付けない。使われていない許可の行は `[注意]` として表示する (終了コードには影響しない)。
許可を足すのは、直すと記録や引用の意味が変わる場合だけにする。

## 試し方

`--root DIR` で別のツリーを検査できる。存在しない番号を書いたファイルを置いた一時ツリーで非 0 になることを確かめる。
