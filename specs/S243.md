## 構成と責務 (T45.2.12、2026-11-05)

catalog を作る Python は、コマンドラインの入口とロジックのパッケージに分かれている。

- 入口 `scripts/wp/*.py` (catalog_build・uncatalogued_build・repost_build・episode_overrides・terms_build・authors_build・work_builder・body_convert・payload_build・docs_build・qa_report・secret_scan・htaccess_block・cluster_review・verify_bodies_html5・qa_phase3_check): 引数の解釈・ファイルの読み書き・表示・終了コードだけを持つ。
- ロジック `scripts/wp/tslib/`: 変換・判定は引数と戻り値だけの関数に置く。モジュールの一覧はパッケージの docstring (`scripts/wp/tslib/__init__.py`)。
  - 共通部分: `paths`・`fileio`・`checks`・`htmltext`・`mail`・`gitinfo`・`slugs`・`kana_index`。
  - 段のモジュール: `catalog/` (目録のパース。catalog_build の分割)・`terms`・`authors`・`works`・`uncatalogued`・`reposts`・`overrides`・`bodies`・`payloads`・`docs`・`qa`。
  - 入口ごとのロジック: `secret_rules`・`htaccess`・`cluster_review`。
  - 独立検算: `verify_html5`・`qa_phase3`。
- 文書の検査: 入口 `scripts/doc_check.py`、ロジック `scripts/doccheck/` (S219)。catalog の道具ではないので `tslib` は import しない。
- 依存の向き: 入口 → 段のモジュール → 共通部分。
  - 段のモジュールどうしは import しない。例外は `docs` → `bodies` (`extract_body`) の 1 本 (T45.2.16)。
  - 独立検算は本体の変換系 (`bodies`・`payloads`・`htmltext`) を import しない (S12)。
  - この 2 つと循環が無いことは `scripts/wp/tests/test_imports.py` が ast で確かめる。
- 決まり: 引数の束 (NamedTuple・dataclass) から出力を機械的に作らない。出力の鍵の順は dict の字面か代入の順で決め、鍵の順を確かめる試験で支える (下の「設計の判断」)。
- git の呼び出しは `tslib/gitinfo.py` だけ (T45.2.18)。自己検査の結果は `tslib/checks.py` の `Checks` で組む (入口に手書きした 3 段は除く。理由は同ファイルの docstring)。

## 設計の判断 (T45.2.19、2026-11-05、高品位なモデルとエフォート)

- **`scripts/doc_check.py` のロジックの置き場:** `scripts/doccheck/` に置く。
  - 文書の検査は catalog の道具ではないので、`tslib` には置かず、`tslib` を import もしない。
  - `python3 scripts/doc_check.py` では `sys.path[0]` が `scripts/` なので、`sys.path` の操作は要らない。
  - 名前を `doc_check/` にすると入口の `doc_check.py` と衝突するので、下線の無い `doccheck` にする。
- **引数の多い 4 関数:** 作られ方がひとまとまりの値だけを束にする。
  - 対で返る値は `typing.NamedTuple` にする。
  - 繰り返しの中で変わらない文脈は frozen dataclass にする。
  - 繰り返しが増やす累計は dataclass にする。
  - 対象は `make_record` (`FileFacts`・`Metadata`)、`work_of` (`WorkContext`)、`report_of` (`PayloadRun`)。`assemble` だけは 1 つの束にせず、戻り値の対 2 組 (`KanaIndex`・`Boards`) を束にする。
  - 出力の鍵の順は、dict の字面を触らないことで守る。規約「束から出力を機械的に作らない」と、鍵の順を確かめる試験もその支えにする。TypedDict、1 つの束にまとめる案、クラスにする案は採らない。
- **`Checks` に揃えるか:**
  - selftest の結果を dict の列に組み直す 4 箇所は、`Checks.as_report()` に揃える。
  - 入口に手書きした `[OK ]` の 3 箇所は揃えない。`format_line` は detail が空でも末尾に空白を付け、旧版の標準出力がそれに依る。3 箇所の手書きの行は空白無しで、その 3 段のレポートには `selftest` の鍵も無い。
